OpenArtifacts: Self-Hosted Artifact Publishing, Versioning & Sandboxed Viewer

A production-grade, self-hosted platform and companion Claude Code skill (/open-artifacts) to publish, version, and share interactive standalone HTML artifacts (dashboards, prototypes, games, data visualizations) with immutable UUID-4 URLs, zero-trust sandbox execution, and lightweight token authorization.

Target Repository
open-artifacts (Public OSS)
Claude Code Skill
/open-artifacts
Deployment Target
Node.js + PM2 on Linux
Primary Stack
Express, Mongo + Disk Hybrid

1. Executive Summary & Vision

Claude Code, AI agents, and developers routinely generate rich standalone HTML files containing embedded CSS, JavaScript, WebGL, Canvas, and React. Today, viewing and sharing these artifacts with clients or colleagues requires sending unwieldy 5MB files over email/chat or configuring heavy cloud hosting. OpenArtifacts provides an ultra-lightweight, self-hostable service that accepts an HTML artifact with a single API call or CLI command, assigns a permanent UUID-4, maintains strict versioning history (v1, v2, v3...), and serves it globally in a secure, zero-trust sandboxed viewer.

2. Problem Statement & Value Proposition

The Problem Today Existing Workarounds & Flaws The OpenArtifacts Solution
Artifacts are trapped in local sessions Sending raw HTML files over Slack or email breaks linked assets, triggers antivirus warnings, and loses live interactivity. Instant Global URL: Publish via CLI or UI to receive an immutable UUID-4 URL (https://artifacts.example.com/a/4f8b2e31-89ab-4c3e-9012-7a8b9c0d1e2f) viewable anywhere.
No Versioning for Iterations Manual renames like report_v1.html and report_v2_final.html create link rot and break client-facing links. Atomic Versioning Engine: Updating an artifact increments version (v1 → v2), while root URL always renders latest and historical versions remain pinned.
XSS & Token Theft on Same Origin Serving arbitrary AI-generated HTML on an internal origin risks stealing admin tokens or persistent service worker installation. Defense-in-Depth Sandbox: Direct /raw responses enforce Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups; yielding an opaque/null origin that cannot touch tokens or cookies.

6. User Stories & Acceptance Criteria

US-1: Upload HTML Artifact via API / CLI (P0) P0
As a developer or AI agent, I want to upload an HTML file with title and description so that I get an immutable UUID-4 viewable link.
  • ✓ Rejects requests with HTTP 401 if token is missing or fails timing-safe pre-hashed comparison.
  • ✓ Validates that file is HTML, under 25MB, and streamed via Multer disk storage (not memory buffer).
  • ✓ Escapes title (max 120 chars) and description (max 500 chars) before storing in DB.
  • ✓ Generates standard RFC 4122 UUID-4 (e.g. crypto.randomUUID()) and creates version 1.
  • ✓ Writes raw HTML to ./data/artifacts/:uuid/v1.html and companion meta.json.
  • ✓ Returns HTTP 201 with { id, version: 1, title, description, url, rawUrl, createdAt }.
US-2: Version an Existing Artifact (P0) P0
As an author, I want to publish an updated version to an existing UUID-4 so that the main link stays intact while preserving previous versions.
  • ✓ Validates id param against strict UUID-4 regex: /^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i. Returns 400 on invalid format.
  • ✓ Returns 404 if UUID-4 does not exist in the database.
  • ✓ Atomically creates version N+1 using MongoDB findOneAndUpdate with $inc: { latestVersion: 1 } and $push: { versions: ... }.
  • ✓ Main URL /a/:uuid automatically routes to the new version; past versions remain accessible at /a/:uuid/v/:n and /raw/:uuid/:n.
US-3: Public Sandboxed Viewer with Top Section & Version Switcher (P0) P0
As a viewer, I want to see the Artifact Name, Description, and Version dropdown at the top, defaulting to the latest version.
  • ✓ Public & Unauthenticated: Viewers require zero login credentials.
  • ✓ Top Header: Displays context-escaped Title, Description subtitle, and created timestamp.
  • ✓ Version Dropdown: Lists all versions in descending order with latest selected by default.
  • ✓ URL State Sync: Switching versions invokes history.pushState() to update URL without full page reload.
  • ✓ Toolbar Controls: Responsive Viewport toggles (Desktop 100%, Tablet 768px, Mobile 375px), Fullscreen expander, Copy URL, Embed snippet, and Raw download button.
  • ✓ Zero-Trust Iframe: Renders inside <iframe sandbox="allow-scripts allow-forms allow-popups allow-modals" src="/raw/:uuid/:version"> omitting allow-same-origin.
US-4: Emergency Artifact Takedown / Delete (P0) P0
As an administrator, I want to delete an artifact immediately if sensitive data was published accidentally.
  • ✓ Endpoint DELETE /api/artifacts/:uuid requires valid ARTIFACT_ACCESS_TOKEN.
  • ✓ Removes database record and safely deletes the artifact directory ./data/artifacts/:uuid from disk.
  • ✓ Returns HTTP 200 with { success: true, message: "Artifact deleted" }; subsequent requests return 404.

7. User & API Flows

[Publish / Update Flow] Client (CLI / Web / Agent) -> POST /api/artifacts (multipart: file, optional id, title, description) -> Check Authorization Token (timing-safe hash comparison) -> [Invalid] -> HTTP 401 Unauthorized -> [Valid] -> Validate File (is HTML, size <= 25MB) -> Validate UUID-4 (if updating existing) or generate new UUID-4 -> Stream to temp file: data/artifacts/tmp/upload-<uuid>.tmp -> Compute SHA-256 hash & extract <title> fallback -> Atomic rename to: data/artifacts/<uuid>/v<version>.html -> Write sidecar: data/artifacts/<uuid>/meta.json -> MongoDB findOneAndUpdate ($inc: { latestVersion: 1 }, $push: { versions }) -> Return HTTP 201 { id, version, url, rawUrl } [Viewer Flow] Public Browser -> GET /a/:uuid or /a/:uuid/v/:version -> Validate UUID-4 and version integer -> Fetch Metadata from MongoDB (or fallback to sidecar meta.json) -> Render Server Shell with Escaped Title, Description, OpenGraph tags -> Embed Iframe pointing to /raw/:uuid/:version (Sandboxed) -> User switches version -> client updates iframe src + history.pushState() [Direct Raw Stream Flow] Iframe / Direct Client -> GET /raw/:uuid/:version -> Validate UUID-4 and version integer -> Send Headers: Content-Type: text/html; charset=utf-8 Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-modals; X-Content-Type-Options: nosniff Cache-Control: public, max-age=31536000, immutable (for pinned versions) -> Stream file from disk via fs.createReadStream()

8. Tech Stack & Architecture

Layer Technology Rationale & Production Configuration
Backend Runtime Node.js (v20+ LTS) + Express.js Standard, robust multipart streaming, zero unnecessary compile step, ES Modules.
Process Manager PM2 Zero-downtime reloads, log rotation, memory limits, automatic Linux systemd boot persistence.
Metadata Store MongoDB + Sidecar meta.json Primary queries via Mongo with indexed UUID-4. Sidecar meta.json on disk guarantees zero metadata loss if Mongo restarts.
Artifact Storage Local Filesystem (./data/artifacts) Multer disk storage streaming directly to ./data/artifacts/:uuid/v:n.html. Instant static pipe.
Security Layer Zero-Trust CSP + Sandbox Headers Enforces opaque null-origin execution on all raw HTML rendering. Eliminates cross-origin token/cookie leakage.
Frontend Vanilla HTML5, CSS3, ES6 JS Lightweight single-file templates with server-side escaping. Zero client-side build pipeline needed.

10. Security & Sandbox Guardrails

🔒 Critical Security Enforcement (Addresses All Vulnerability Vectors):
  • Opaque Origin Sandboxing on /raw: All raw artifact routes respond with Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-modals; and X-Content-Type-Options: nosniff. This gives the rendered artifact an opaque/null origin so it can NEVER read parent cookies, access localStorage, or install service workers.
  • Never Store Auth Token on Same Origin: The upload portal does not persist tokens in long-term unpartitioned cookies. API tokens are passed strictly in request headers (Authorization: Bearer <token> or x-access-token).
  • Path Traversal Defense: Strict regex validation on :uuid (UUID-4 format only) and :version (positive integers only). File paths are strictly resolved via path.join() and verified to remain within STORAGE_PATH.
  • Stored XSS Prevention: All user-supplied fields (title, description) are HTML-escaped using a robust entity escaper before interpolation into viewer templates, <title>, and og: meta tags.
  • Timing-Safe Token Comparison: Tokens are pre-hashed using SHA-256 before invoking crypto.timingSafeEqual() to guarantee fixed-length buffers and prevent length-oracle attacks:
    function verifyToken(providedToken, secretToken) { if (!providedToken || !secretToken) return false; const hashA = crypto.createHash('sha256').update(String(providedToken)).digest(); const hashB = crypto.createHash('sha256').update(String(secretToken)).digest(); return crypto.timingSafeEqual(hashA, hashB); }
  • Strict Framing Policies: Viewer Shell (/a/:uuid) sends Content-Security-Policy: frame-ancestors 'none'; to prevent clickjacking on the outer chrome. Raw Endpoint (/raw/:uuid/:version) allows framing with sandboxing for the embed feature.

11. Error Taxonomy & HTTP Status Codes

All API error responses follow a standardized structured JSON format.

// Standard Error JSON Structure { "error": { "code": "INVALID_UUID_FORMAT", "message": "The provided artifact ID must be a valid UUID-4 string.", "status": 400 } }
HTTP Status Error Code Trigger Condition
400 Bad Request INVALID_UUID_FORMAT id parameter is not a valid RFC 4122 UUID-4 string.
400 Bad Request INVALID_FILE_TYPE Uploaded file is not a valid .html file or is empty (0 bytes).
401 Unauthorized UNAUTHORIZED Missing or invalid ARTIFACT_ACCESS_TOKEN in request headers.
404 Not Found ARTIFACT_NOT_FOUND Artifact with specified UUID-4 does not exist.
404 Not Found VERSION_NOT_FOUND Requested version number does not exist for this artifact.
413 Payload Too Large FILE_TOO_LARGE Uploaded artifact file exceeds configured MAX_FILE_SIZE_MB (25MB).
429 Too Many Requests RATE_LIMITED Upload rate limit exceeded (30 req/min) or read rate limit exceeded (120 req/min).
500 Internal Error INTERNAL_SERVER_ERROR Unexpected filesystem or database failure.

12. Out of Scope (Explicit MVP Boundaries)

The following features are explicitly deferred from the v1 MVP:
  • ❌ No multi-user authentication / OAuth / Signups: Single environment variable token for publishers.
  • ❌ No public search directory or explore gallery: Artifacts remain unlisted and accessible only with the exact UUID-4.
  • ❌ No multi-file project bundler / zip unpacker: Artifacts are standalone single-file HTML (with inlined CSS/JS/images).
  • ❌ No automated screenshot generation / headless browser rendering: OpenGraph cards use high-contrast branded card fallbacks.
  • ❌ No billing, Stripe, or monetization layer.

13. Risks & Mitigations

Risk Description Likelihood Impact Mitigation Strategy
Malicious JS uploaded in artifact attempting XSS / credential harvesting Medium High Strict sandbox header on /raw isolates origin to null. Omission of allow-same-origin completely blocks cookie & storage access.
Concurrent updates causing lost versions / file collision Low Medium Temp file streaming → atomic filesystem rename → MongoDB findOneAndUpdate with atomic $inc and $push.
Home Server MongoDB brief downtime Low Medium Dual-write writes meta.json alongside raw HTML files on disk, enabling disk-level fallback.
Memory spikes under concurrent 25MB uploads Low High Multer configured with diskStorage to stream directly to filesystem rather than buffering in Node.js RAM.
